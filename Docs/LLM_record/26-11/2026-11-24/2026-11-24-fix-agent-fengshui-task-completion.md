# 2026-11-24 修复 Agent「分析某地风水」提前停止

- **日期与时间**：2026-11-24 15:20
- **任务等级**：L2（Agent 编排与提示词）
- **版本**：V3.7.11

## 问题

用户问「分析广东省汕头市澄海区峰下村的风水」，Agent 只输出：

1. 已完成坐标解析；
2. 说明需要先定位并启用罗盘；
3. 显示「工具调用已执行」；
4. 停止。

预期行为：先定位 OL / Cesium 双视图到目标，再启用罗盘，最后提示用户点击卦象继续分析。

## 根因

1. **提示词缺少「分析某地风水」的串行工作流**。现有规则只区分「当前范围风水 → enable_compass」与「定位某地 → search_and_zoom」，没有把两者串起来。
2. **后续轮指令鼓励提前总结**。首轮工具执行后的 user 指令写着“如果工具执行成功，告诉用户已完成什么操作”，模型因此把「坐标解析完成」当成任务完成。
3. **geocode 是只读工具**，不会移动地图；模型调用它后自然认为已得到坐标，却未继续执行。
4. **双视图定位会超过现有 4 轮上限**。OL + Cesium 各自定位需要切换视图、搜索、切回、启用罗盘，至少 5~6 步。
5. **重复调用检测不区分视图**。同样的 `search_and_zoom(query)` 在 OL 与 Cesium 各执行一次会被误判为重复调用。

## 修复

### 1. 系统提示词新增任务完成契约

明确：

- 工具执行不是交付，只有用户目标全部完成才能总结；
- 禁止用「工具调用已执行」作为终结性回复；
- 「分析某地风水」完成标准 = 双视图定位 + 罗盘启用 + 提示用户点击卦象；
- `geocode` 不能替代 `search_and_zoom`；
- 若用户指定 OL 和 Cesium 都要定位，必须分轮切换视图并分别定位。

### 2. 多轮编排提示改为「对照原始任务」

首轮与后续轮都把 `userMsg` 原文带入：

```text
原始任务：{userMsg}
若未完成，必须直接调用下一个工具；只有完成全部步骤或需要用户输入才总结。
```

### 3. 编排上限 4 → 6

满足「双视图定位 + 启用罗盘」流程；纯定位 / 图层操作仍保持原轮数。

### 4. 重复签名加入视图维度

`stableToolSignature(calls, view)` 把当前 `mapContext.view` 纳入签名，避免 `search_and_zoom` 在两个视图被误判重复。
