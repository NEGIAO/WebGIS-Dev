## 一、需求分析

### 1.1 需求

罗盘参数中有中心点经纬度（`compassStore.position`），把它提取出来一并发给 Agent，让 Agent 结合「这块地在哪」做地方性分析 —— 例如同一个「子」山，落在杭州西湖区与落在黄土高原，环境解读应当不同。

### 1.2 路线选择：谁来做逆地理编码？

| 路线 | 做法 | 评价 |
|---|---|---|
| A. Agent 自己调工具 | 给 `AGENT_TOOLS` 新增 `reverse_geocode` 工具，提问里只给坐标 | 多一轮工具调用往返；需要扩工具 schema + adapter + 白名单，改动面大；且模型可能不调用 |
| B. **前端先逆地理，地名写进提问** | 提问前调 `apiReverseGeocodeWithFallback`，把省市区/地址/坐标一并写进文本 | 零新工具、零额外往返；模型开门即见地名；失败可降级为仅坐标 | **采用** |

**选定 B**。核心理由：逆地理编码是**确定性数据获取**，不是需要推理的任务 —— 放在前端做比交给模型又快又稳；且系统提示已声明罗盘问答「无需调用任何地图工具」，路线 A 会与该约束打架。

### 1.3 现有能力复用（不新写网络调用）

- 统一入口 `apiReverseGeocodeWithFallback(lng, lat)`（`@/api`）：高德优先、天地图兜底，内部自动 WGS-84→GCJ-02，返回归一化的 `{ formattedAddress, province, city, district, township, adcode, businessAreas, provider }`
- 罗盘 `position` 由 OL `toLonLat` 产出 = WGS-84，与该入口的输入契约**天然匹配**，无需转换
- 坐标系契约见 `api/geocoding.ts` 头注释（上层调用方无需感知 GCJ-02）

## 二、实施内容

### 2.1 `PalaceExplanationPanel.ts`

- 注入 `useCompassStore`（取中心点）与 `apiReverseGeocodeWithFallback`
- `buildAgentQuestion()` 改为 **async**：基础文本（主题/层号/层名/宫位名）+ `buildLocationContext()` 拼接
- 新增 `buildLocationContext()`：
  - 有效性检查：`lng/lat` 为有限数且不全为 0（`(0,0)` 是「从未设置」的默认值，落在几内亚湾）
  - 调用统一逆地理入口，拼 `province+city+district+township`（空串过滤，直辖市 city 为空时自然降级）
  - **三重降级**：地名齐全 → 完整句；只有地址 → 用地址兜底 region；服务失败/坐标无效 → 仅附坐标或返回空串，**提问照常发出，绝不因逆地理失败而丢功能**
- `handleAskAgent()` 顺序调整：**先 `requestOpenChat()` 再 await 逆地理** —— 逆地理有数百毫秒网络延迟，先开面板给用户即时反馈，避免「点了没反应」的观感；提问稍后经队列投递，时序由既有消费守卫保证

### 2.2 i18n 新增两键

| 键 | 场景 | 文本要点 |
|---|---|---|
| `compass.askAgentLocationNamed` | 逆地理成功 | 位于{region}（{address}），坐标 {coords}；要求结合地形地貌、水系、气候、人文格局做贴合当地的解读 |
| `compass.askAgentLocationCoord` | 逆地理失败 / 无地名 | 仅坐标 {coords}，请基于所在区域一般地理特征分析 |

### 2.3 最终提问示例

```
请解释风水罗盘「地理专业版」第 4 层「二十四山」中「子」的含义：包括它的卦象与五行属性、
对应方位、吉凶判断依据，以及在风水实践中的典型用法和需要注意的禁忌。这是本平台罗盘功能的
内置咨询，请直接以知识解答，无需调用任何地图工具。罗盘中心点位于浙江省杭州市西湖区
（浙江省杭州市西湖区文三路×××），坐标 120.129721, 30.259242（WGS-84）。请在分析中结合
该地的实际地理环境——地形地貌、水系分布、气候特征与人文格局——给出贴合当地的解读。
```

## 三、影响范围

| 模块 | 影响 |
|---|---|
| 宫位释义按钮 | 点击后先开侧栏（即时反馈），约数百毫秒后投递带地点的提问 |
| 聊天会话 | 用户消息更长（多一句地点上下文），其余链路不变 |
| 后端 | 复用既有 `/api/proxy/amap/geocode/regeo` 代理，无新接口 |
| Agent 服务 | 无新工具、无 schema 变更；系统提示上一轮的「无需调用工具」约束保持一致 |

**降级矩阵**：

| 场景 | 行为 |
|---|---|
| 逆地理成功 | 提问含省市区 + 详细地址 + 坐标 |
| 高德失败、天地图成功 | 提问含天地图解析结果（字段同构） |
| 两者都失败 | 提问仅含坐标句 |
| 坐标为 (0,0) 或无效 | 不附地点句，提问与 V3.7.30 版本一致 |

   - **预期**：侧栏立即展开；用户消息中出现「罗盘中心点位于浙江省杭州市西湖区（…），坐标 …」

2. 把罗盘中心移到西北内陆再点一次
   - **预期**：提问中的地名随之变化；回答的地理语境切换（黄土/干旱等）
3. 断网或后端代理不可用时点击
   - **预期**：侧栏照常展开，提问仍发出（仅含坐标句），功能不中断
4. 罗盘中心在境外（如东京）
   - **预期**：高德解析可能失败或返回空 → 降级为坐标句；回答仍可基于经纬度推断气候带

## 五、遗留与风险

1. `apiReverseGeocodeWithFallback` 走后端代理，**计入后端对高德的调用配额**；频繁点击会累积消耗。未做防抖（单次点击仅一次调用），如后续需要可加节流。
2. 逆地理结果未缓存：同一位置反复提问会重复请求。属可接受的低频操作。
3. 高德对境外坐标通常解析失败 → 稳定走「仅坐标」降级，属预期行为。
