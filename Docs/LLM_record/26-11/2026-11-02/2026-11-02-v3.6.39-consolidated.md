## 一、问题分析

### 1.1 核心症状

起因是一条第三方统计记录 `http://webgis.negiao.cn:5173/#/home?ut=admin`，据此怀疑「有人绕过 HTTPS、访问 dev 端口、并以管理员身份通过鉴权」。排查过程中同时发现三个真实的配置与鉴权缺口。

### 1.2 根本原因

| # | 现象 | 根因 |
|:--:|---|---|
| 1 | 统计里出现任意域名 + 5173 | 51.la 采集脚本以 `cu = location.href` 作为 query 参数上报，无签名；`window.location` 与采集端均可由客户端构造，URL 不具备身份证明力 |
| 2 | dev server 可被任意域名访问 | `vite.config.js` 的 `host: '0.0.0.0'` + `allowedHosts: true`；本机实测 `curl -H "Host: webgis.negiao.cn:5173"` 返回 200 |
| 3 | 管理入口可见性可被前端篡改 | `isAdmin` 读 `sessionStorage` 缓存，用户手工改 `role` 即可显示管理页签（数据仍被后端 403 拦截，但状态分裂） |
| 4 | 管理员口令可无限次尝试 | `/login` 的 admin 分支只做 `hmac.compare_digest`，无失败计数、无锁定 |
| 5 | CORS 生产等于全放行 | `CORS_ALLOWED_ORIGINS` 为空 → `["*"]` + `allow_credentials=True` |
| 6 | 限流若按 IP 会被绕过 | `X-Client-IP` / `X-Forwarded-For` / `X-Real-IP` 全部由客户端可写 |

### 1.3 受影响模块

后端：`api/auth/{routes,constants,throttle}.py`、`api/admin.py`、`app.py`、`config/catalog.py`、`deploy/.env*`。
前端：`common/user/components/FloatingAccountPanel.vue`、`locales/{zh-CN,en-US}.js`、`common/shell/TopBar.vue`、`common/url-state/stores/useUrlParamStore.ts`、`common/user/services/auth.js`（后三者仅注释/类型调整）。
文档：新增 `Architecture/identity-auth-security.md`，同步结构树与版本记录。

## 二、过程与试错（4 个中间版本）

| 中间版本 | 做了什么 | 结果 |
|---|---|---|
| 初版 | 删除 `ut` URL 标记 | **误判**。`ut` 是统计分组与人工排查的真实用途，删除砍掉观测手段 |
| 第二版 | 恢复 `ut`，新增 `utt = sha256(会话令牌)[:12]` + 管理员回查接口 | **无效**。统计 URL 由客户端控制，URL 内任何标记都无法证明身份，只是增加维护面 |
| 第三版 | 撤销 `utt`，新增登录失败节流（账号优先） | 保留 |
| 第四版 | 节流阈值改为 L1 环境变量（5 次 / 60 秒 → 锁 60 秒） | 保留 |

结论沉淀为架构文档 §3.1：**鉴权只认 `Authorization` 头里的会话令牌，其余一切（URL、客户端 IP、Origin、前端缓存）都不参与授权。**

## 三、修改内容（最终净改动）

1. **CORS fail-closed**：`app.py` 空值不再回退 `["*"]`，改为空列表 + warning；`deploy/.env` 登记 9 个前端来源；`.env.example`、`catalog.py` 描述同步。
2. **管理入口后端判定**：`isAdmin` 改读 `useAuthStore().user.role`（仅由 `/api/auth/me` 写入）；`selectMenu` 进入管理页签前 `await apiAdminOverview()`，403 收回入口、401 交由全局拦截器；身份变化时重置 `adminDenied`。
3. **登录失败节流**：新增 `api/auth/throttle.py`（进程内滑动窗口，账号 5 次 / IP 30 次，窗口与锁定各 60 秒），`/login` 入口判 429 + `Retry-After`，失败记数、成功清零。
4. **IP 提取加固**：`_first_valid_ip` 过滤非法头值，注释声明非信任边界。
5. **配置登记**：新增 4 个 `LOGIN_THROTTLE_*` L1 key。
6. **架构文档**：`Docs/Architecture/identity-auth-security.md`（2 图 6 表）。
7. **传输层约束**：`deploy/nginx.conf` 增加 server 级 `if ($http_x_forwarded_proto ~* "^http$") { return 403; }`，覆盖全部 location；同时把 `X-Forwarded-Proto` 由「覆盖成 `$scheme`（恒为 http）」改为透传边缘值。文档 §7 拆为前端/后端两行，新增 §7.1（HSTS 必要性）与 §7.2（容器侧实现与回滚方式）。

## 四、修改原因

- 把「可见性」「口令尝试成本」「跨源调用」三件事从客户端约定收回到服务端判定；
- 不引入新表、新密钥：节流用进程内状态，CORS 用现有 L1 配置；
- 观测手段（`ut`）与信任判定彻底分离，避免再次用 URL 推断身份。

---

## 五、影响范围

- 登录失败返回 `429`（原统一 401），前端 `client.js` 已能解析 `detail.code/message`；
- 非法 IP 头不再原样写入 `sessions.ip`；
- 管理入口在会话失效后不再闪现；
- 新增一个前端请求（首次打开管理页签的探活），约 1 个 RTT。

---

## 六、解决方案与关键决策

| 决策 | 取舍 |
|---|---|
| 节流不落库 | 建表属数据库结构变更（L3）；当前单 worker 部署，进程内计数即全局计数 |
| 账号维度为主 | IP 可伪造，只按 IP 限流可被逐次换头绕过 |
| CORS 空值 fail-closed | 宁可新增域名时接口报错（显式暴露），也不默认全放行 |
| 不用 Cloudflare 限流 | API 域名为 `negiao-webgis.hf.space`，不经过 CF，规则无效 |
| 不改 `ut` | 无读取方，删除会砍掉观测手段；加签名无法证明身份 |

## 十一、遗留与风险

1. **多 worker 失效**：节流状态在进程内；当前单 worker 成立，改多 worker 需换共享存储。
2. **重启清零**：滚动发布期间窗口重置，攻击者无法主动触发。
3. **游客配额可绕过**：`guest_uid` 由可伪造的 IP 派生，理论上可无限领取额度（配额滥用，非越权）。
4. **令牌明文入库**：`sessions.token` 未做摘要存储，库泄漏等于会话全失（表结构变更，属 L3）。
5. **第三方脚本供应链**：`min-enhanced.js` 不在本仓库，可被替换为任意 JS 读取 sessionStorage。
6. **dev server 仍在 `0.0.0.0:5173` 监听**：`host` 与 `allowedHosts` 未收敛，局域网可达；要不要改为 `127.0.0.1` 待用户确认（L1 级改动）。
7. **缺少登录审计视图**：失败/成功登录未在管理后台可查，排查「是否被爆破」仍需看日志。
