## 问题分析

### 核心症状
- 登录页依赖 `t('auth.*')`，但 `core.js` 原先仅有 `common`，完整包在 `await loadPreferences` 之后才懒加载 → 首屏可能短暂泄漏 key 路径
- `FALLBACK_LANG = en-US` 与 `getMessage` 硬编码回退 `zh-CN` 不一致；chunk 失败时 merge 进 fallback 槽位，当前语言仍取不到
- `messages` 对 `coreMessages` 仅浅拷贝，`deepMerge` 污染模块级常量
- `localeLoaded` 为全局布尔，切换语言后依赖调用方手动 `loadLocaleMessages(true)`，易漏
- RegisterView 残留硬编码 a11y 文案与头像 label

### 根本原因
- V3.4.70 懒加载拆分后，首屏键集合与加载时序未对齐
- fallback 策略在「写槽」与「读链」两端未统一
- 语言切换未收敛到单一入口

### 受影响模块
- `useLocale` 国际化核心
- 登录/注册页、偏好语言切换、用户偏好 bootstrap
- 语言包 core / zh-CN / en-US

## 修改内容

### 1. `useLocale.js` 正确性加固
- `cloneLocaleNode` 深拷贝 core，避免污染 `coreMessages`
- `loadedLocales: Set` + `inflightLoads: Map` 按语言去重
- `setLocaleLanguage` 自动触发 `loadLocaleMessages`（变化或未加载）
- 失败时把 fallback 文案 **merge 进当前语言槽**
- `getMessage` 回退链：当前语言 → `FALLBACK_LANG` → `zh-CN` → path
- merge 后 `messages.value = { ...messages.value }` 触发顶层响应
- import 路径统一带 `.js`

### 2. 首屏与加载时序
- `core.js` 同步纳入登录首屏 `auth.*` + `preferences.language/languages`
- `main.js` mount 前 `void loadLocaleMessages()`
- `bootstrap` 在 `loadPreferences` **之前**触发加载（与网络并行）

### 3. 调用方收敛
- PreferencesTab / RegisterView 去掉手动 `loadLocaleMessages(true)`
- FloatingAccountPanel 注释标明依赖 setLocaleLanguage 自动加载

### 4. RegisterView a11y
- `modeSwitchAria` / `avatarGroupAria` / `avatarOption` 全 i18n

### 5. 文档
- 修正 V3.4.70 CHANGELOG 中「线上致命 bug」措辞：改为「改 ref 时同步修正访问」
- 本日志 + CHANGELOG + README 版本三处
