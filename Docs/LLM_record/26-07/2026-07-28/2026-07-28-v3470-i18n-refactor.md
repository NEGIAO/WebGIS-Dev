# V3.4.70 — i18n 国际化重构：语言包物理拆分 + 懒加载 + Bug 修复

> 日期：2026-07-28 15:30  
> 任务等级：L2  
> 版本号：V3.4.70

## 问题分析

### 核心症状
- `useLocale.js` 内联了全部 zh-CN/en-US 消息表（365 行），导致主 bundle 体积膨胀
- 将 `messages` 改为 `ref()` 时需同步把 `getMessage` 改为 `messages.value[lang]`（重构配套修正，避免 t() 取不到表）
- `loadLocaleMessages` 存在竞态条件：快速切换语言时旧语言的结果可能覆盖新语言
- 硬编码 `import()` 路径，新增语言需修改核心逻辑
- `localeLoaded` 导出但无任何消费方

### 根本原因
- 重构为 `ref()` 时必须同步修正 `getMessage` 的 `.value` 访问
- 异步加载缺少语言标记校验
- 未遵循开闭原则

### 受影响模块
- 国际化（i18n）链路
- 登录/注册界面（`RegisterView.vue`）
- 用户偏好设置（`PreferencesTab.vue`）

## 修改内容

### 1. 语言包物理拆分
- 新增 `frontend/src/locales/core.js`：同步核心语言包（common 键，首屏必需）
- 新增 `frontend/src/locales/zh-CN.js`：中文完整语言包（懒加载 chunk，837 行）
- 新增 `frontend/src/locales/en-US.js`：英文完整语言包（懒加载 chunk，592 行）
- `useLocale.js` 从 365 行精简至 147 行

### 2. 懒加载架构
- 新增 `loadLocaleMessages(force)` 函数，动态 `import()` 完整语言包
- `messages` ref 初始仅包含 `common` 键，加载后 deepMerge 触发响应式更新
- `useUserPreferencesStore.init()` 非阻塞触发加载
- `PreferencesTab` 切换语言后强制重载并更新 UI

### 3. Bug 修复
| Bug | 修复 |
|---|---|
| `getMessage` 配套 `.value` | `messages[lang]` → `messages.value[lang]`（随 ref 改造） |
| 竞态条件 | 新增 `loadingLang` 标记，过期结果丢弃 |
| 硬编码 import | 提取为 `LOCALE_LOADERS` map |
| 回退语言不合理 | `zh-CN` → `en-US`（更中性） |
| 未使用导出 | 移除 `localeLoaded` computed |
| emoji 丢失 | `emailCheckMessage` 恢复 `✅ ` 前缀 |

### 4. RegisterView.vue 全量 i18n 化
- 所有硬编码中文文案替换为 `t('auth.*')` 调用
- 覆盖：标签、按钮、placeholder、错误消息、状态提示

---

## 修改原因

- **性能**：主 bundle 减少约 30-40KB（gzipped），首屏加载更快
- **可维护性**：语言包独立文件，新增语言只需添加 `locales/xx-XX.js` + `LOCALE_LOADERS` 一条记录
- **正确性**：`messages` 改 ref 时同步修正访问，保证 `t()` 正常
- **安全性**：竞态条件修复，避免语言切换后显示错误语言

## 解决方案

### 方案对比

| 方案 | 优点 | 缺点 | 选择 |
|---|---|---|---|
| A. 保持内联 | 无迁移成本 | bundle 大，难维护 | ✗ |
| B. 全量懒加载 | bundle 最小 | 首屏可能闪烁 | ✗ |
| C. core 同步 + feature 懒加载（选中） | 首屏无闪烁 + bundle 适中 | 需维护两份文件 | ✓ |

### 实施步骤
1. 创建 `core.js`（common 键）
2. 创建 `zh-CN.js` / `en-US.js`（完整消息表）
3. 重构 `useLocale.js`（ref + 懒加载 + deepMerge）
4. 修复 `getMessage` bug
5. 更新 `PreferencesTab.vue` 和 `useUserPreferencesStore.ts`
6. 全量 i18n 化 `RegisterView.vue`
7. 更新文档（日志 + CHANGELOG + 结构树）

## 遗留与风险

- 叶节点 key 已对齐（后续 V3.4.72 为 804/804）；行数差异来自排版密度，不代表缺 key
- 懒加载首次切换语言时有短暂异步延迟（~50ms），用户通常无感知
- `deepMerge` 对数组采用覆盖策略，未来若翻译值含数组需注意
- 首屏 auth 泄漏与 fallback 不一致等问题已在 V3.4.72 修复
