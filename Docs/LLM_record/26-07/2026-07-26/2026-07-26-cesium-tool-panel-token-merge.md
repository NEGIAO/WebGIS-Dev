## 问题分析（事件逻辑链条）

| 环节 | 内容 |
|------|------|
| 核心症状 | `CesiumToolPanel.vue`（2686 行）暗色风格样式内散布大量硬编码色值，改观感需全文件搜替、P3-1 拆分子组件时色值将随行复制漂移 |
| **规划口径纠偏** | 规划写「56 处硬编码」——实测 **232 处色值字面量**（≈115 个不同值）：56 只统计了 hex 色，rgba() 族 ~170 处漏计；其中 9 处 `white` 实为 `white-space` 属性误计。**实际收编对象 = 223 处（218 替换 + 5 豁免）**。已按 Force_command「规划与现状不符先报告」暂停并获用户确认全量口径 |
| 根本原因 | 面板早于令牌治理成形，且刻意独立暗色（不随绿/蓝主题联动），此前令牌化轮次均未覆盖 |
| 受影响的模块 | `CesiumToolPanel.vue`（仅 style 块）、新增 `assets/cesium-tool-theme.css`、`App.vue`（一行 @import）、`frontend-structure.md`（登记） |
| 方案 | **-rgb 基色分解模式**（仓库现成先例：`--brand-primary-rgb`）：同色相多 α 档收敛为一个 `--ctp-x-rgb` 三元组令牌，α 语义留在使用处（如冰蓝 155,216,255 一色相 18 档 α → 1 令牌）；实色用同名实色令牌。不并入 `--panel-*`、不挂 `[data-theme]`，保持独立暗色身份 |

## 修改内容

1. **新增 `frontend/src/assets/cesium-tool-theme.css`**（72 行，:root 上 `--ctp-` 前缀，仿 toc-theme.css 组织）：
   - 29 个 `-rgb` 基色令牌：冰蓝主强调（43 处）、白系薄层（33）、冰蓝亮文本（20）、活性绿（15）、暗海军蓝面族 7 项、深绿选中/展开族 7 项、警示红黄族 4 项等；
   - 19 个实色令牌：主强调绿 `#3ddc84`（14 处）、主文本/标题/页签/图标等文本族、警示实色、纯白、下拉底等；
   - 文件头写明域约定：独立暗色身份不随主题联动；P3-1 拆分子组件时复用本文件禁止回退硬编码。
2. **`CesiumToolPanel.vue` 218 处脚本化机械替换**：162 处 `rgba(R,G,B,α)` → `rgba(var(--ctp-x-rgb), α)`（α 原样保留）+ 56 处 hex → `var(--ctp-x)`。
3. **5 处刻意豁免（防御性 var 兜底字面量，逐个理由）**：`var(--text-primary, #1e293b)` ×2、`var(--brand-primary, #2f9a57)`、`var(--acc-text-soft, #5d7f6a)`、`rgba(var(--brand-primary-rgb, 47, 154, 87), …)`——均已是令牌化写法，兜底参数若再套变量将丧失兜底意义。
4. **`App.vue`**：`@import './assets/cesium-tool-theme.css'`（紧随 toc-theme.css，同位同模式）。
5. **`frontend-structure.md`**：assets/ 树登记新文件（含功能注释，字母序插位）。

## 修改原因

规划 P2-2 的既定目标：56→实测 232 处硬编码导致该面板观感不可维护；P3-1 拆分前先收敛色值，拆分时子组件天然共享域令牌文件。

## 影响范围

- 视觉：**零变化**（见测试方案的等值还原证明）
- 运行时：CSS 变量解析开销可忽略；`:root` 上仅新增 48 个 `--ctp-` 前缀自定义属性，与现有令牌无命名交集
- 主题切换：不受影响（--ctp-* 不挂 [data-theme]，暗色身份恒定）
- template/script：零改动

## 解决方案（实施要点）

替换全程脚本化执行（非手工逐处），正则按精确三元组/hex 匹配、α 捕获组原样回填；`rgba(var(...))` 开头的既有令牌写法天然不被数字开头的正则命中，零误伤。

## 性能指标

- 无（纯样式等值替换）。
