## 2. 解决方案

### 方案选型（Example_prompt.md）

| 方案 | 评估 | 结论 |
|---|---|---|
| A. 直接删除 | 内容确实全部过期，但会丢失"用户如何下达任务"这一层——`Force_command.md` 只规定 Agent 侧行为，用户侧无任何指引 | 否决 |
| B. 修正三处错误表述，保留原填空结构 | 原结构是单次配额任务的专用模板，修好也无法复用于其他任务类型 | 否决 |
| C. **重写为通用任务启动模板库** | 补上规范的"用户侧入口"，与 Force_command 形成「怎么下达 ↔ 怎么执行」的闭环 | **采用** |

### 实施内容

**① `Docs/Example_prompt.md` 重写（43 → 约 140 行）**

- **定位声明**：明确与 `Force_command.md` 的分工——后者规定 **Agent 怎么执行**，本文提供 **用户怎么下达**，不重复规范内容只做引用。
- **通用开场白**：固定两句（"完整阅读 Force_command.md" + "先声明任务等级"）。因用户已决定不新建根 `CLAUDE.md` 自动加载入口，Agent 不会主动读取规范文件，**这句话是规范生效的唯一开关**，故置于文首单列一节。
- **四类模板**：
  - **A Bug 修复** —— 现象 / 复现步骤 / 期望行为 / 已知线索 / 约束（含"顺带发现记入 TODO 而非顺手改"）
  - **B 功能开发** —— 目标 / 功能点 / 交互与边界（含 **"不做什么"**，防范围膨胀）/ 验收标准 / 约束（含封装要求与配置 key 登记顺序）
  - **C 重构（L3）** —— 显式写明"先只输出方案，等确认后再动代码"，含"只搬不改""分批可独立回滚"两条硬要求
  - **D 审计（L0）** —— 声明只读不改，输出按 P0–P3 分级并汇入 `bugfix-optimization-plan.md`
- **收尾验收表**：8 项对照 DoD 与交接块，附一句提示——缺项时回「按 Force_command 第 7 节补齐 DoD」即可，无需逐条复述。

**② `Docs/Guide/dev-conventions.md`**

删除尾部 15 行游离段落，替换为「相关文档」导航表（Force_command / Example_prompt / handover / dev-guide 四项），使该文件结尾从"无关残留"变为"向外指路"。

**③ `Docs/Guide/project-structure.md`**

两行注释纠偏：`Example_prompt.md` 由「Agent 提示词示例」→「任务启动提示词模板（Bug/功能/重构/审计）」；`Force_command.md` 由「Agent 强制命令」→「Agent 强制执行规范（权威）」。

### 关键设计决策

- **删除操作先报后删**：上一任务按新规范第 2 节第 4 条「禁止删除本次任务范围外的内容」将游离段落列入遗留项而非直接删除，本次经用户确认后才执行——这是新规范硬边界的一次实际生效记录。
- **模板按任务类型分岔而非做成万能表单**：与 `Force_command.md` 的 L0–L3 分级一一对应（D↔L0、A/B↔L2、C↔L3），用户选模板即等于定级，降低"等级判错"的概率。

## 6. 遗留与风险

- **规范生效仍依赖人工开场白**：无自动加载入口时，若用户忘记带上"请阅读 Force_command.md"，Agent 大概率不会主动读取，整套规范失效。当前以 `Example_prompt.md` 文首单列一节作为提醒，**属流程性缓解而非机制性保证**。若实测遗漏率高，建议重启根 `CLAUDE.md` 方案。
- **`Docs/Guide/` 其余文件未做同类体检**：本次只处理了已知的两处残留，`dev-guide.md`（61 行）、`faq.md`（53 行）是否也存在过期表述或幽灵引用尚未核查，建议后续做一次 L0 只读审计（可直接套用新增的模板 D）。
- **历史日志中的失效指引不予修正**：`26-04` 等早期日志正文引用了旧路径与旧约束，按规范"历史不迁移"保持原样，读旧日志时需注意其规范口径已过期。
