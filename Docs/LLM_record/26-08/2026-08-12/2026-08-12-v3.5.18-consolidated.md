## 问题分析

暂存区积累多次改动（Emoji→Lucide 图标迁移、AdminControlPanel 数据管理重构、KaTeX 数学公式渲染、聊天配置按模式隔离、新闻降级链路加固），需要进行 Code Review 后统一修复并发布版本。

**核心症状**：暂存区 20 个文件，+1158/-656 行，包含多个主题的改动，部分代码存在安全漏洞和 bug。

**根本原因**：多次改动未经 Review 直接暂存，积累了以下问题：
- `useMarkdownRenderer.js`：模块级可变状态导致并发渲染竞态；`trust: true` 配置引入 XSS 风险
- `AdminControlPanel.vue`：v-for 中 ref 只引用最后一个元素；单元格编辑与行展开编辑状态冲突
- `SidePanel.vue`：共享 AbortController 导致超时窗口不足；HTTP 错误不降级
- `Force_command.md`：被写入了口语化的注释

**受影响模块**：Markdown 渲染（Agent 对话）、管理控制台（AdminPanel）、新闻功能（SidePanel）、UI 图标规范

**候选方案对比**：
1. 直接提交暂存区 → 不推荐，存在安全和 bug 风险
2. Review 后修复再提交 → ✅ 选定方案

## 修改内容

### 1. Force_command.md 规范化
- 移除硬边界章节的口语化注释（"我整个项目的原则就是尽量不要用emojo 能用lucide就用lucide"）
- 在第 3 节「实施」章节新增「UI 图标规范」条款：统一使用 `@lucide/vue`，禁止使用 emoji

### 2. useMarkdownRenderer.js 安全修复
- **并发安全**：将模块级 `mathStore`/`mathCounter` 改为 `createMathContext()` 工厂函数，每次渲染独立上下文
- **XSS 修复**：移除 KaTeX `trust: true` 配置，改为 `trust: false`
- **DOMPurify 白名单扩展**：加入 KaTeX 输出标签（math/semantics/mrow/mi/mo/mn 等）
- `renderAnswerHtml` 和 `renderThinkHtml` 均使用新的隔离上下文 API

### 3. AdminControlPanel.vue Bug 修复
- **cellInputRef 修复**：将 `ref="cellInputRef"` 改为 `:ref="setCellInputRef"` 函数 ref，避免 v-for 中 ref 被覆盖
- **编辑互斥**：`startEditCell` 中添加 `if (editingRowKey.value !== null) return`，行展开模式下禁止单元格编辑
- **图标语义**：agent tab 从 `Globe` 改为 `Bot`（更准确表达"模型"语义）

### 4. SidePanel.vue 降级链路加固
- 直连和代理请求使用**独立 AbortController**（原共享导致超时窗口不足）
- HTTP 非 ok 响应也纳入降级判断（原只有网络错误才降级）

## 修改原因

- **安全**：KaTeX `trust: true` 允许执行潜在危险内容；并发竞态导致公式渲染失败
- **正确性**：v-for 中 ref 覆盖是 Vue 3 的常见陷阱；编辑状态冲突导致 UI 异常
- **规范**：Force_command.md 是 L3 规范文件，不应被写入口语化注释

## 解决方案

| 问题 | 方案 | 实施文件 |
|------|------|----------|
| 并发竞态 | createMathContext() 隔离 | useMarkdownRenderer.js |

| 规范注释 | 移至「实施」章节正规条款 | Force_command.md |
