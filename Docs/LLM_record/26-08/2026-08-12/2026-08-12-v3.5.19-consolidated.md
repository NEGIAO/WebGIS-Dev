# V3.5.19 合并版本：实时在线统计体系 + 时区/IP 定位加固（整合日志）

## 日期与时间
2026-08-12（合并整理于 2026-08-13）

## 任务等级
L2（综合：功能开发 + 多轮 Bug 修复 + 重构）

## 版本背景
本版本为**暂存区多轮未提交改动的合并**。此前暂存区以 V3.5.19~27 多个临时版本号迭代实时统计逻辑，同时夹杂 V3.4.63 遗留的时区/IP 定位改动，版本号与日志均不规范。经用户指示：全部整合为单一版本 **V3.5.19**，代码注释收敛、日志合一、README/CHANGELOG 仅保留一条 V3.5.19 条目。

## 问题分析（按主题）
1. **实时在线统计不可靠（核心主题）**：历经多轮迭代最终确定为「心跳模型」：
   - 旧实现信号源混杂（请求活跃事件 + SSE 连接状态 + 断开事件 + offline 上报），每种信号都有误报/漏报窗口，补丁叠加导致「实时性」与「稳定性」互相打架；
   - 用户设计正确模型：前端每 5s 主动上报心跳（唯一标识 = 用户 ID），后端 15s 窗口内有心跳 = 在线，停心跳自动剔除，每 15s 广播人数。
2. **游客在线不可见**：游客不建 SSE 连接，且轮询端点只返回 DB 登录会话口径（游客不在内）→ 在线数与真实脱节。
3. **时区错误（V3.4.63 遗留）**：全站时间按 UTC 存取，国内用户统计口径（日期、在线窗口、备份命名）与北京时间偏差 8 小时。
4. **IP 定位失真（V3.4.63 遗留）**：Docker 环境 `request.client.host` 是容器网关 IP；ip-api.com 免费版仅 HTTP 且不稳定。
5. **SSE 鉴权泄露面**：完整会话 token 曾可经 query param 传参（事件流场景），会落入代理日志/浏览器历史。

## 修改内容
### A. 实时在线统计（核心）
- **心跳模型**（最终形态）：
  - 前端 `useRealtimeStats.js`（模块级单例）：全局（HomeView 挂载）启动，每 5s POST `/api/statistics/heartbeat`；`visibilitychange` 切回前台立即补发；SSE 仅承担每 15s 推送通道；心跳定时器幂等（重连不累积）。
  - 后端 `realtime_stats.py`：`OnlineUserTracker` 单信号窗口模型（15s 窗口、按身份去重）；`POST /api/statistics/heartbeat`（登录/游客皆可，响应携带 online 数作兜底展示）；SSE 端点（一次性短时 ticket 鉴权 + 15s 定时/即时广播）；**删除** `/api/statistics/disconnect`。
  - 身份唯一性：登录 username / 游客 device_id 派生 uid；同身份多标签去重为 1 人；`mark_user_active`（鉴权中间件）等价心跳。
- **游客接入**：未登录访客恒发 `X-Guest-Device-Id`（sessionStorage 每标签独立）；`_is_guest_allow_request` 凭设备头放行；ticket/SSE/心跳对游客开放；`statistics.py` 新增 `_merge_online_tracker` 使 center/realtime 轮询端点与 SSE 广播口径一致（含游客）。
- **鉴权收口**：`_extract_token` 不再接受 query token（V3.5.19 起事件流改用 ticket）。

### B. 时区（V3.4.63 遗留，归并）
- 全站时间改为北京时间（UTC+8）：`auth/db.py`（`_utc_now`/`_iso`/`_parse_iso`/备份命名）、`admin.py`、`api_management.py`、`api_keys_management.py`、`agent_chat/utils.py`、`api/location.py`、`download_xyz/*`、`utils/sqlite_maintenance.py`、`utils/sqlite_recovery.py`；`sessions.last_seen_at` 触活节流 60s→15s 适配实时推送。

### C. IP 定位（V3.4.63 遗留，归并）
- `_extract_client_ip` 优先信任前端 `X-Client-IP`（前端经 ipify 获取公网 IP，3s 超时 + 30s 负缓存）；
- 私有 IP 检测 `_is_private_ip`（ipaddress 库），私有/内网 IP 直接跳过定位或返回 400；
- 定位服务新增 ipwho.is 优先（免费、HTTPS、不屏蔽数据中心 IP），catato 登记 `IP_GEO_IPWHO_ENDPOINT`。

## 修改原因
统一起见：实时统计是用户多次反馈"人数不对"后的最终方案；时区与 IP 为历史遗漏修正；全部整合为 V3.5.19 单一版本便于提交与追溯。

## 影响范围
实时统计（tracker/SSE/心跳/游客）、鉴权（guest allow/device id/token 收口）、时区（全站数据库时间语义）、IP 定位（前端头/私有 IP/服务优先级）、配置（`IP_GEO_IPWHO_ENDPOINT` 已登记）。**端点变更**：新增 `/api/statistics/heartbeat`、`/api/statistics/ticket`、`/api/statistics/stream`；删除 `/api/statistics/disconnect`——前后端需同步发布。

## 解决方案
实时在线统计采用用户设计的心跳模型（对比多信号补丁方案，后者废弃）；时区统一北京时间并在 `_parse_iso` 兼容旧 `+00:00` 数据；IP 定位以"前端上报公网 IP + 私有 IP 预防 + ipwho.is 优先"三层修复。

## 性能指标
心跳 12 req/min/客户端（100 在线 ≈ 20 req/s 轻量 POST）；SSE 广播 15s/次；未压测。

## 遗留与风险
- 后台标签页定时器节流（浏览器限制）→ 后台页心跳中断被踢，切回前台恢复；如需恒在线需 Web Worker 心跳（未做）。
- 游客 identity 依赖 IP+UA+device_id 哈希；换网络 IP 变 → 同访客生成新 guest 记录（语义取舍，未改）。
- guest device_id 客户端可伪造 → 游客配额/计数可刷（游客体系无强身份，设计取舍）。
- `_utc_now` 函数名仍带 UTC 字样但实际返回北京时间（命名地雷，暂未改名，注释已说明）。
- 心跳端点每请求一次 DB 会话查询，规模数百级可加 token 内存缓存（未做）。
