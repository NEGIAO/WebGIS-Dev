## 问题分析

### 核心症状
1. 地图下载在 watch 自动触发路径下使用 `window.open`，Chrome 在非用户手势上下文弹窗拦截 → 用户感知"静默后台运行、无进度可见"。
2. 下载 store `applyTaskResponse` 不回填 `basemap_name` → 任务卡不显示底图名。
3. 下载 store 存在 `markDownloaded`/`downloadedAt` 死代码 + `estimateTileTimer` 泄漏。
4. bbox watch 与 `estimatedTileCount` watch 双重触发配额估算（重复请求）。
5. `mapDownload.quotaInsufficient` i18n key 缺失 → EN 界面露中文 / 文案不统一。
6. Chat 第二轮 LLM 调用 catch 吞掉 429 → false success；`lastCallCost` 跨请求残留；`useChatAgentConfig` 硬编码中文。
7. 定位失败 toast 无 `silent` 门禁；管理员 tokens-per-unit 加载/保存竞争；BusPlanner 死条件分支。
8. Dockerfile entrypoint 非 root 跑 `cron` 静默失败（sudoers 未用）；`api_management` 守卫不建 `api_usage_daily`；`agent_tokens` 写死 1000。

### 根本原因
- 下载链路设计时未区分「用户手势触发」与「watch 自动触发」两种上下文，前者可用 `window.open`，后者必须用隐藏锚点。
- 多轮对话 catch 块未区分错误类型，一律降级为成功摘要。
- 后端模块建表守卫各自为政，未考虑初始化顺序。

### 受影响模块
下载链路、Chat 配额提示、定位、管理员面板、公交规划、后端运维（cron / 配额表 / agent 配置）

### 候选方案对比

| 问题 | 方案 A | 方案 B | 选定 |
|---|---|---|---|
| 自动下载弹窗拦截 | 恢复 blob-fetch 作为 watch 默认 | 改用隐藏锚点 `triggerUrlDownload` | B（用户明确要求浏览器托管 + Chrome 可见进度） |
| bbox 双估算 | 删 `estimatedTileCount` watch | 删 bbox watch 内的 `estimateCurrentCost` | A（保留单一触发源，时序一致） |
| agent_tokens 回退 | 保留写死 1000 | 回退到 `get_int("AGENT_TOKENS_PER_UNIT")` | B（尊重 env/catalog 默认） |

### 选定方案与理由
- 下载：后端 `download_task_file` 已返回 `Content-Disposition: attachment`（download.py:326），隐藏锚点可在无手势上下文触发浏览器原生下载，Chrome 下载栏可见进度，满足用户"不静默后台"要求。
- 配额提示：区分 `isQuotaExceeded` 与一般错误，分别处理。
- 后端：兜底建表 + env 回退，消除初始化顺序依赖与写死常量。
