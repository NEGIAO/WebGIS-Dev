## 问题分析

- 核心症状：暂存区混装同日 4+ 个会话批次（TOC 重命名修复 / 区划字段修复 / 落地页南师大重构 + 主卡预览图 / TopBar 与属性弹窗 UI / 游客序号后端链），版本记档分裂为 V3.6.20 与 V3.6.21 两条（README 三处版本号不一致：简介 V3.6.20、表与页脚 V3.6.21）；且落地页新代码存在部署级隐患。
- 根本原因（审查发现的缺陷链）：
  1. 项目 vite base 默认 `'./'`（GitHub Pages 子路径 `/WebGIS/` 部署），CSS 内绝对路径 `/fonts/...`、`/images/...` 不经打包器改写，子路径下必 404——`@font-face`（字体静默失效）与轨道环 mask（mask 失效退化为整块金色圆面）双双命中；
  2. 自托管思源宋体只声明了 `@font-face`，无任何 font-family 栈引用（死字体）；
  3. 落地页本批新增导航控件未按本批新立的「移动端基线」给 `pointer: coarse` 触屏档（34px < 40px）；
  4. `lastDispatchError` 异步成功分支不清旧错误（诊断信息陈旧）。
- 受影响模块：前端落地页（LandingView/theme.css/SectionTitle）、图层操作路由（unifiedActionRouter）、文档治理（README/CHANGELOG/结构树/日志）。

## 补录（2026-10-17 16:52 · 第二会话）：后端 guest_no 快速路径修复

> 本日志主体审查时后端 auth 链被显式排除（影响范围注明"不涉及后端逻辑"）。第二会话按同一用户诉求补审后端暂存改动（`git diff --cached -- backend/`），发现并修复一处死路径。归并版本号不变，仍为 V3.6.20。

### 问题分析

- 核心症状：`routes.py::_public_user_payload` 注释宣称"优先取调用方显式传入的值（如登录分支已在建会话前拿到）"，但全仓检索证实**无任何调用方传入**——`session["guest_no"]` 永远不存在，游客分支每次构造 payload 都回查 `guest_identity_records`（`_get_guest_no_sync`，同步 sqlite 调用直接跑在事件循环里，违背本文件全仓 `asyncio.to_thread` 包裹 DB 的既定惯例）。
- 根本原因：`dependencies.py::_build_temporary_guest_session_async` 拿到 `guest_record["no"]` 后丢弃只取 username；`login_user` 游客分支同样丢弃；`_build_login_response` 无 guest_no 入参，注释承诺的快速路径是死代码。
- 受影响模块：`backend/api/auth/dependencies.py`、`backend/api/auth/routes.py`；前端展示链不变（`useAuthIdentity` 优先读 `user.guest_no`，本次不动）。

### 修改内容

1. `dependencies.py`：临时游客会话新增 `"guest_no"`（自 `guest_record["no"]`），临时游客路径的 payload 不再回查库。
2. `routes.py`：`_build_login_response` 新增可选入参 `guest_no: int = 0`，建会话后注入 `session["guest_no"]`（仅内存传递，`sessions` 表不加列、不做迁移——加列属 L3）；`login_user` 游客分支传入该值。

### 修改原因

消除"注释宣称的快速路径永不命中"的死代码与游客 payload 构造中的冗余同步查询；`/me` 等从库读回的历史会话仍走现查兜底（`guest_uid` 带 UNIQUE 索引，单次索引查代价可忽略，不构成性能问题）。
