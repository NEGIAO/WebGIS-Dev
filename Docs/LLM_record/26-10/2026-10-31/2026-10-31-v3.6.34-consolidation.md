# 整合多次不规范暂存提交为单一版本 V3.6.34

- **日期与时间**：2026-10-31 完成
- **任务等级**：L2 常规
- **目标版本**：V3.6.34

---

## 一、问题分析

### 核心症状

暂存区存在多次不规范的小提交信息，且同一批改动被拆分为 V3.6.34 / V3.6.35 / V3.6.36 三个版本号，而 HEAD 实际停留在 V3.6.33，五份改动从未分开发版。违反 Force_command §5「同一批次不得拆成多个版本号」，需整合为一个统一的版本 V3.6.34。

### 根本原因

开发过程中连续多次 `git add` / 逐次记版本，未按 §5 合并为单一修订号；版本号、CHANGELOG、README 三处未同步。

### 受影响模块

- 前端：首屏打包链（vite.config.js、main.js、stores 深导入、defineResilientAsync）、TIF/GeoTIFF 解码链（tifUtils.js、olRemoteServiceAdapter.js）、移动端 UI（LandingView、RegisterView、GlobalLoading、CesiumContainer、MapControlsBar 等）
- 文档：README.md 三处版本号、CHANGELOG.md 版本记录、frontend-structure.md 新增 defineResilientAsync.ts
- 无后端、无配置 key 新增

## 二、修改内容

1. **版本号整合**：README.md 三处版本号统一为 V3.6.34（当前版本 / 版本演进表首行 / 页脚），版本演进表三行改为 V3.6.34（整合）/ V3.6.33 / V3.6.32。
2. **CHANGELOG 合并**：将 staged 中的 V3.6.36（TIF 按需加载）+ V3.6.35（首屏优化）+ 原 V3.6.34（移动端主题）三个条目合并为单一 V3.6.34 条目，子项重新编号 A~O，保留完整技术细节与验证记录。
3. **代码审查与潜在 Bug 修复**：
   - `tifUtils.js`：四个顶层重依赖（geotiff ~309 kB / ol/source/DataTile / ol/layer/WebGLTile / ol/source/GeoTIFF）已下沉为函数内按需 `import()`，仅在真正解码 TIF 时加载，未引入新 Bug。
   - `olRemoteServiceAdapter.js`：`import { XYZ } from 'ol/source'` 桶导入已改为子路径 `ol/source/XYZ.js`，消除 dev 下进入 OL 后 ~680 ms 误拉 geotiff 的问题。
   - `main.js` / `LandingView.vue` / `RegisterView.vue` / `GlobalLoading.vue`：均从 `../stores` / `@/stores` 聚合桶改为深导入单一 store 文件，切断 `export *` 无法 tree-shake 的路径。
   - `useAuthStore.ts` / `useUserPreferencesStore.ts`：`@/api/backend` 静态导入已改为在「已登录」分支内按需 `import()`，axios 退出首屏预加载图。
   - `defineResilientAsync.ts`：新增带占位 / 线性退避重试 / 超时兜底的异步组件工厂，修复移动端分片挂起时「整块 UI 空白」问题。
   - 移动端关闭钮由文本 `×` 改为 Lucide `X` SVG，修复 iOS 不居中；符合「禁止使用 emoji 作为图标」规范。
4. **文档与结构树**：`frontend-structure.md` 新增 `defineResilientAsync.ts` 条目；`CheckStructureTree.py` 522/522 通过、`CheckConfigRegistry.py` 7 项全通过。

## 五、解决方案

方案：同一批次合并为单一版本号，不拆分发版。三个原版本的全部代码改动保留，版本号统一为 V3.6.34，CHANGELOG 三个条目合并为一个，README 版本演进表恒定三行（V3.6.34 / V3.6.33 / V3.6.32），各阶段过程记录仍按原样保留于 `Docs/LLM_record/`，不回溯改写历史日志。
