## 一、问题分析

### 1.1 核心症状

暂存区（index）累积了 50 个文件、**9077 insertions / 451 deletions** 的改动，横跨绘制/测量、图层样式、地形贴合、贴地重构四条线；`CHANGELOG.md` 里这批改动被逐次记为 **V3.6.24 / V3.6.25 / V3.6.26 / V3.6.27 / V3.6.28 五个版本号**，而 `HEAD` 实际停留在 `V3.6.23`（`git log` 首条业务提交 `4f1b3247 V3.6.23`）。

### 1.2 根本原因

1. **版本号语义被误用**：§5 规定「L2/L3 任务各自 +1 修订号」，但同一批**从未分开发版**的改动被当成五次独立发版递增。后果是 README「版本演进」表里出现 25/26/27 三个未发布版本，版本号与 git 历史脱钩。
2. **同一批次多轮迭代的中间态直接写进了发版文档**：每轮迭代都把当轮结论写成一条 CHANGELOG 条目，导致条目之间互相覆盖（例如 V3.6.26 新增的 `terrainFitService.js` 在 V3.6.27 被删除，两版条目并存会让读者以为该文件仍存在）。
3. **新建 `.js` 违反 TS 优先**：§2.11 要求新建逻辑文件默认 `.ts`，但本批次新增的 4 个前端逻辑模块全部是 `.js`（`drawMeasureSpec` / `drawEntityFactory` / `browserIo` / `cesiumLayerSerialization`）。
4. **审查发现的实现缺陷**（见 §三.3）。

|---|---|
| 版本体系 | README 三处 + CHANGELOG 五条 → 一条 |

### 3.2 缺陷修复

**① 透明度非法值导致整层「消失」**（`useCesiumDrawMeasure.js` + `drawEntityFactory.ts`）

- 原：`const o = Math.min(1, Math.max(0, Number(opacity) || 0))`——`undefined` / `NaN` 经 `|| 0` 折算为 0，即**全透明**；`drawEntityFactory` 的 `baseAlpha` 若为 `undefined`，`withAlpha(NaN)` 会让实体整片不可见，且不报错。
- 改：非法值回落 1；新增 `finiteOr(value, fallback)` 统一兜底 `baseAlpha` / `fillOpacity`。

**② 矢量线色改不动**（`dataImport/dataSourceDisplay.js`）

- 原：判定「纯色材质」只认 `ColorMaterialProperty`。而 `GeoJsonDataSource` / KML 载入后 `polyline.material` 常是**裸 `Color` 实例**，被判定为非纯色 → 换色被静默跳过，表现为「点样式设置没反应」。
- 改：补 `material instanceof Cesium.Color` 分支。

**③「编辑要素」出现在不支持的类型上**（`cesiumLayers.ts` + `cesiumLayerNodeBuilder.ts` + 管理器）

- 原：能力位判据只有 `record.category === 'draw'`，而绘制成品的 `record.type` 只能是 `draw`/`route`，无法区分具体几何类型 → 矩形 / 圆 / 测高距 / 方位角也显示「编辑要素」，点开必然提示「不支持」。
- 改：`CesiumLayerRecord` 增 `shapeType`；`registerDrawing` 接收并落库；节点能力位改读 `drawMeasureSpec.EDITABLE_TYPES`，与管理器 `startVertexEdit` 共用同一判据。

**④ 死变量清理核验**：`CesiumContainer.vue` 的 `_rsvcSetHeight` 随 `setBaseHeight` 改走门面一并删除，全文件实测残留引用 **0 处**。

## 四、修改原因

1. **版本号必须可追溯**：`3.6.25/26/27` 三个号在 git 历史里不存在对应提交，读者按 CHANGELOG 找提交会落空。归并到 `3.6.24` 后，`V3.6.23 → V3.6.24` 与 HEAD 连续。
2. **条目互斥性**：V3.6.26 引入的 `terrainFitService.js` 在 V3.6.27 被删除，两条并存会误导后续接手者。合并为一条后只描述**最终态**。
3. **TS 覆盖率**：`tsconfig.json` 的 `include` 只含 `src/**/*.ts` 与 `src/**/*.vue`，`.js` 完全不受类型检查。迁移后这 4 个模块进入 `tsc --noEmit` 视野，字段改名/漏传能被静态发现。
4. **缺陷优先级**：①②③ 都属于「静默失效」类——不报错、不崩溃，只是功能不生效或误显示，最容易被实机验收漏过。

## 九、遗留与风险

1. **git 索引与工作区已不一致（必须由用户处理）**：本次按要求**未执行任何 git 写操作**。由于 4 个文件是文件系统级重命名，索引里仍是「`A *.js`」，工作区里已是 `*.ts`（untracked）。用户需自行执行 `git add -A frontend/src/domains/cesium` 让索引跟上，再提交。另：本会话保存文件后索引被环境自动更新（`git diff --stat` 为 0 行可证），**非本会话执行 `git add`**。
2. **`Docs/Demo/DrawManager.js` 保留 `.js`**：属 §2.11 明列例外（`<script src>` 直载、无构建链路）。若要求全仓无 `.js` 逻辑文件，需为 Demo 引入编译产物，属独立立项。
3. **本次未修、已记 TODO 的发现**：
   - `applyVectorDataSourceStyle` 会把 `entity.label.fillColor` 一并改成填充色，深色底图上标注可能失去对比度（语义存疑，需产品确认）；
   - `en-US.js` 相对 `zh-CN.js` 缺 204 个键（含 `controls.style / styleEdit / applyStyle`），英文界面会回落中文——**HEAD 既有缺口**，非本批次引入；
   - `setMeasureOptions` 触发的全量重算会覆盖 TOC 右键的单条「关闭标注」状态（已知设计限制，注释已说明）。
4. **§11.2 红线自查的两类误报**：① 原始命令未排除 `backend/.venv`（`.gitignore:90` 已忽略），会命中 `numpy` 的 `hermesub`、`uvicorn` 的 `start_keepalive`；② 红线 2 的 `xray` 与 Cesium 云层参数 `xRay` / `maxRayDistance` 大小写不敏感冲突（36 处）。建议给四条命令统一加 `--exclude-dir=.venv` 并把 `xray` 收紧为 `\bxray\b`，已记 TODO。
5. **版本号不可回退风险**：若他处并行会话已使用 `V3.6.24` 之外的编号，按 §5「后完成者顺延」处理；本次以用户指定的 `V3.6.24` 为准。
